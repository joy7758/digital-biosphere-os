# Standards Hardening Roadmap

This roadmap is a working draft for hardening the ecosystem toward clearer
candidate-layer materials. It does not claim that the stack is already
standardized.

## Phase 1: architecture clarity

- tighten layer boundaries and explain what each repository is responsible for
- document where candidate interaction and evidence layers fit in the stack
- keep the narrative spine stable across repositories and demos
- reduce ambiguous wording about what is architecture framing versus current implementation

## Phase 2: conformance and evidence fixtures

- define threat models that match the current evidence and control surfaces
- stabilize baseline conformance vectors and expected pass/fail behavior
- index reviewable fixtures, receipts, and example artifacts
- keep exportable evidence as the default review surface for demos and audit flows

## Phase 3: interop and external adapters

- identify adapter paths for external runtimes without treating them as mandatory
- publish candidate interop profiles for receipts, evidence bundles, or validators
- document optional integration points with governance and execution-integrity components
- invite external review on bounded verification surfaces before broader standard claims
