# Vienna Poster Q&A Pack

## Q1. Is this already an FDO standard?

No.

It is a discussion-ready architecture with candidate FDO-facing entry artifacts.

## Q2. What is the strongest candidate artifact?

For public routing, start with the architecture hub.

From there, Agent Evidence is the concrete execution-evidence entry,
Verifiable Agent Demo is the shortest walkthrough, and ARO-Audit is the
post-execution audit control plane.

Within the current FDO-facing discussion, POP and AIP remain strong object and
interaction-semantics candidates, while ARO-Audit remains an audit-layer
candidate.

## Q3. Why not present this as one big profile?

Because the architectural layers play different roles.

Some parts are object/profile candidates, some are verification surfaces, and some are reference implementations.

## Q4. What is new here relative to general AI agent frameworks?

The focus is not only capability.

The focus is governance, execution integrity, and exportable audit evidence.

## Q5. Why is MVK not framed as a profile?

MVK is mainly a verification and conformance surface.

Its value is in replay validation, deterministic checks, and tamper detection.

## Q6. What does ARO-Audit add?

ARO-Audit turns runtime actions into bounded and reviewable evidence artifacts with integrity and provenance-oriented references.

## Q7. What do you want from the FDO community?

Feedback on profile boundaries, terminology alignment, and whether these entry artifacts fit existing FDO discussion patterns.

## Q8. What is the practical outcome if this direction works?

A clearer path for representing governed autonomous AI systems in terms that are structured, reviewable, and interoperable.
