# FDO Dataspace Outreach Texts

## English Short Version

Digital Biosphere Architecture is the canonical architecture hub for the
project. Agent Evidence Profile (AEP) in `agent-evidence` is the concrete
execution-evidence entry for portable, independently verifiable evidence
bundles, while `verifiable-agent-demo` provides the shortest walkthrough and
`aro-audit` covers post-execution review and conformance. The EDC Java spike
should be described only as a frozen augmentation-layer validation artifact:
EDC is used here as a scenario-specific dataspace augmentation environment, not
as the research mainline.

## English Standard Version

Digital Biosphere Architecture is the canonical architecture hub that explains
repository boundaries and the main entry path across architecture, evidence,
demo, and audit. Within that structure, Agent Evidence Profile (AEP) in
`agent-evidence` is the concrete execution-evidence entry for portable,
independently verifiable evidence bundles; `verifiable-agent-demo` is the
walkthrough surface for the shortest end-to-end path; and `aro-audit` is the
audit plane for post-execution review, receipts, and conformance. In FDO or
dataspace discussions, the EDC Java spike should be described narrowly as a
frozen augmentation-layer validation artifact. It validates a scenario-specific
control-plane augmentation path, but EDC is not the research mainline and the
spike is not an EDC product line or replacement.
