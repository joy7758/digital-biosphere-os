## Candidate access boundary

Future access, if separately approved, would be service access through a
versioned contract. It would not be a license to TITMAS private core source,
internal tests, policy weights, private Git history or Provider configuration.

The contracting principal would remain accountable for Agent selection,
requests, credentials, legal basis, data minimization and final disposition.
TITMAS responses would remain bounded machine outputs rather than legal,
scientific or compliance conclusions.

This draft defines no endpoint, availability promise, formal price, customer,
SLA, jurisdiction or active Permission.
